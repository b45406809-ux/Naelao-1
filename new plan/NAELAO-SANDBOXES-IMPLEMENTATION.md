# Naelao managed computers and sandbox infrastructure

## Scope and source

This implementation follows the infrastructure conversation in `Compare_Agent37_Infrastructure.txt` (messages beginning around source lines 4, 419, 1146, 2080, 2403, 2790, 3103, 3815, 5959, 6588, 6734, 7465, 8158, and 8834). The accompanying CSV is the requirement/evidence index. User requirements are distinguished from assistant-proposed prices, claims, and designs.

The user-approved first implementation scope was the core computer platform: per-project computers, a shared-file-system boundary, Agent37/OpenSandbox and existing Cloudflare execution options, desktop, API/SDK/MCP, billing, and AgentPort connector support. Marketplace, GPU hosting, Python SDK, and a broad replacement of Cloudflare services were deferred. The checked-in work implements an additive control-plane foundation and UI configuration surface. Several runtime paths remain explicitly gated as recorded below; this is not a claim of full provider integration.

## Architecture findings and decisions

1. Project files are canonical in the Agents worker's R2 bucket under `spaces/{space}/projects/{project}/workspace/`; branch workspaces use `branches/{branch}/` below that prefix. RepositoryDO keeps a Git projection and is not the file authority. The sandbox worker does not receive `SCRIPTS_R2`: it calls a private Agents service route, keeping unrelated scripts, credentials, and extension artifacts outside the new worker's authority.
2. `workers/agents/container/artifact-fs.mjs` is an explicit hydrate/read/write/flush API wrapper; it does not mount FUSE and native guest filesystem calls do not transparently reach R2. `RepositoryDO` has public tree/object reads but no public mounted commit route. The new bridge therefore exposes immutable snapshots and explicit staged blobs, not a POSIX mount.
3. Existing `ToolSandboxDO` keeps its guest snapshot and pending journal in its own Durable Object storage. External provider workers cannot safely attach to that container or its private storage. The bridge instead persists snapshot/blob authorization and publication idempotency in D1, stages content in a bridge-only R2 prefix, then uses the same per-file `ConcurrencyDO` fencing/CAS primitive as ToolSandbox. This preserves one canonical writer primitive while allowing a provider-neutral caller. A pending publication can be retried: already-applied desired hashes are recognized, and staged blobs remain retained while the journal is pending.
4. The execution ladder already provides deterministic six-tier routing, tenant budget reservation, grants, and an authorized local bridge. It should remain the orchestrator. `naelao_sandboxes` is a new explicit Tier 6 backend identifier, not a replacement for native/WebContainer/Cloudflare/local routing. Air-gap policy still rejects all non-local compute.
5. Agent37 control credentials and instance-plane credentials are different. Current primary docs (checked 2026-11-06) document `POST https://api.agent37.com/v1/instances`, `X-Agent37-Key` at `https://sandbox.agent37.app/v1/instances/{id}/exec`, derived instance URLs `https://{id}.agent37.app`, and file APIs on agent templates. This corrects the older snapshot's assumption that all operations use the control host. The exec `name` is safe to replay for five minutes, but create has no documented idempotency header; metadata is recorded only for future reconciliation. The generic command API does not guarantee cancellation, Naelao workspace conflict semantics, binary-safe durable diff publication, or protocol-level desktop view-only/takeover. Agent37's desktop is a custom VNC template and signed URL, not a general remote-desktop API.
6. OpenSandbox's lifecycle API can create/pause/resume/delete resources, but the project's own docs and deployment topology must supply the execution protocol, persistent volume, ingress, and desktop gateway. A generic Docker host on a VPS does not imply safe persistent state, pause billing, or authenticated GUI access.
7. The D1 schema is additive. The bridge adds expiring snapshot/blob authorization rows and an idempotent publication key on existing publication records. Snapshot data is copied into a separate `sandbox-workspace-bridge/` R2 prefix; canonical project keys change only through an explicit fenced publication. Snapshot metadata carries the executable flag, while Cloudflare's 1 MiB base64 CAS limit caps files at 768 KiB. Worker subrequest budgets cap a snapshot at 200 files and a publication at 100 changes; callers batch larger diffs against the same unexpired snapshot. Existing Space, project, and grant records are not rewritten. Erasure removes staged bridge objects before deleting their D1 authorization rows.
8. Per-file compare-and-swap can provide atomicity per object and an honest recoverable journal, not all-files-at-once transactions. For concurrent project writers, retain fenced per-file CAS and surface conflicts; only a coordinated exclusive workspace lease can promise a consistent multi-file snapshot among cooperating writers.
9. Desktop streaming needs a server-side protocol gate that strips input events in view-only sessions and a generation-fenced human takeover lease. Existing screenshot/action APIs are bound to the Cloudflare ToolSandbox runtime and do not create a portable browser desktop. No UI-only `viewOnly` flag would be sufficient.
10. Current Agent37 billing docs list $0.80/vCPU-month, $0.70/GB-month RAM, and $0.09/GB-month disk; default 2 vCPU/4 GB/4 GB is $4.76 when awake all month. VM compute is 2.5x default, Performance compute 4x default, and disk remains unchanged. Sleeping instances bill disk only; the docs give about $0.54/month for a 2 vCPU/4 GB instance awake one hour/day. These current-source values supersede earlier transcript numbers or assistant math. Cost estimates belong in integer micros with source, region, effective time, and allocation assumptions. The current helper captures those assumptions only for an estimate; it does not bill. Existing billing must reserve before allocation and reconcile uncertain provider outcomes before settlement.
11. Cloudflare Containers pricing is usage based, metered per active 10 ms: $0.000020 per additional vCPU-second, $0.0000025 per additional GiB-second, and $0.00000007 per additional GB-second of disk. A Workers Paid plan currently includes 375 vCPU-minutes, 25 GiB-hours of memory, and 200 GB-hours of disk monthly; container network egress has region-specific rates and allowances. Compare with actual awake-time/resource traces and subtract included allowances before estimating a bill. An always-allocated monthly multiplier is not a valid Cloudflare comparison. This source data is verified from the Cloudflare Workers pricing page, but the Naelao account's plan and usage are not.
12. The current OpenSandbox primary docs confirm the `/v1/sandboxes` lifecycle surface, API-key header, pause/resume operations, and SDKs, but its isolated-execution docs explicitly state `/diff` and `/commit` are not implemented by the current execd. That means it can be a compute substrate, but its native isolated filesystem cannot serve as Naelao's durable BYOFS publication layer. The current adapter is a non-routed scaffold: the service does not expose it as available until request/response schemas, endpoint token forwarding, persistence, ingress, egress policy, and failure semantics are acceptance tested. Sources checked 2026-11-06: OpenSandbox [API reference](https://github.com/opensandbox-group/OpenSandbox/blob/main/docs/api/index.md), [JavaScript/TypeScript SDK](https://github.com/opensandbox-group/OpenSandbox/blob/main/docs/sdks/javascript.md), and [deployment overview](https://github.com/opensandbox-group/OpenSandbox).

## Alternatives and recommendation

| Option | Advantages | Practical cost / risk | Decision |
|---|---|---|---|
| Keep Cloudflare ToolSandbox as Naelao's default Tier 6 | Already integrated with grants, cancellation, project scoping, R2 hydration, staged publication, and recovery. No new host fleet. | Cloudflare usage charges can add up at high CPU/RAM duty cycles; existing desktop APIs are tied to this runtime. Measure actual traces against included allowances. | Keep for normal Naelao execution and reuse its workspace journal. |
| Agent37 BYO compute | Managed lifecycle, sleep behavior, desktop templates, API; current documented baseline is $4.76/month awake for 2 vCPU/4 GB/4 GB. | Requires two credentials/hosts for control and exec, a Naelao guest/template, and a separate R2 bridge. Generic commands do not give process cancellation or atomic workspace publication. | First external provider once the workspace bridge and live acceptance exist. |
| OpenSandbox on managed or customer Kubernetes/Docker | Open-source, documented lifecycle and SDKs, infrastructure control, multiple runtimes. | Naelao/operator owns deployment, upgrades, capacity, storage, ingress/egress policy, and API availability. Current execd lacks isolated diff/commit; API access URLs may require per-endpoint headers/tokens. | Keep as a provider adapter option; do not use it as shared project storage. |
| Direct Hetzner/OVH VMs | Potentially cheaper raw CPU and storage; avoids provider-specific sandbox lock-in. | Raw VM cost is not a sandbox product: Naelao would build secure provisioning, image lifecycle, isolation, scheduling, persistent storage, network policy, desktop gateway, monitoring, and on-call recovery. Historical quotes in the conversation were not verified current prices. | Defer until measured demand justifies operating a host fleet. |

Recommendation: keep the existing execution ladder and ToolSandbox path as the near-term Naelao runtime; build one narrow Agents-owned snapshot/diff bridge; then let verified Agent37 and OpenSandbox adapters provide compute behind the same contract. This follows the repository's recent history: commits `e93a65f9` and `eefb5405` introduced staged dynamic sandbox execution and hardened guest/workspace boundaries, while `3ef39290` added scoped shared filesystems and `44ab0d0a` preserved installed sidecar identity. Replacing these mechanisms with a generic FUSE assumption would discard recovery and isolation work that is already present.

## Deliberate incomplete gates

The implementation now exposes the R2 snapshot/staging/publication bridge. Provider-backed start/sleep/delete, a pinned guest protocol, provider execution journaling, desktop stream/action/takeover routes, standalone API-key permission enforcement, MCP handlers, AgentPort provider connector, billing reservations/usage settlement, saved browser profiles, and full shell GUI remain gated. Agent37 and OpenSandbox are still unavailable until live provider credentials, guest protocol acceptance, and lifecycle reconciliation are verified. `/sync` returns `filesystem_bridge_unavailable` only when the Agents service binding is absent; the providers do not yet use it to start or execute a remote guest.

## Safe continuation order

1. Ship a pinned Naelao guest runtime protocol and test it inside the existing root-owned supervisor/unprivileged guest boundary before linking provider allocation.
2. Add encrypted, tenant-bound provider connections and live verification/reconciliation; prove unknown-create recovery before scheduling.
3. Wire Agent37 and OpenSandbox clients to that protocol with provider acceptance tests and strict capability/region/egress checks.
4. Add stream gateway and protocol-level view-only/takeover fencing; add UI controls only after its server authorization exists.
5. Integrate existing billing reservations and usage receipts, then wire SDK, MCP and AgentPort to shared handlers and independent grants.
6. Run connected provider and desktop acceptance tests, migration/rollback validation, full CI suites, and inspect the uploaded suite result JSON before enabling rollout.
