## Additional repository discrepancies found by this cross-source pass

1. **Direct-worker/planner chronology requires both turns.** The user asked for both paths, then later deferred broader swarm expansion. Correct status: retained future direction, deferred implementation; do not list it as a current implementation gap.
2. **Customer bot kind removal was previously easy to overstate.** It removes the database discriminator and genericizes template application, but channel ingress still executes the hardcoded customer-bot prebuilt. The custom-extension migration is still open and must not be reported complete.
3. **The older sources' structural-kind count is contradictory and not user-ratified.** The code's use of generic `workspace` after kind retirement is compatible with the confirmed customer-kind correction; the exact future set of UI/layout primitives is unresolved.
4. **Project-to-subspace status must distinguish logical grouping from physical migration.** The accepted direction is present as logical reparenting. Moving data/processes to a new SpaceDO and rewriting all runtime references remains explicitly incomplete; older zero-copy/instant-migration claims are not evidence.
5. **Pricing questions remain unresolved despite metering work.** The early user request asks for simple plans and bundled first-month template purchases; current resource usage accounting alone does not answer how customers and FDEs are charged or how template price and subscription revenue are split.
6. **Media-only support is intentionally capability-bounded.** The early request and later continuation support tool-driven media handling; do not mark the entire multimodal idea done based only on classification/transcription or generated provider examples.

## Remaining implementation order

1. Define an explicit worker-failure recovery contract; preserve authorization boundaries and surface failures instead of silently falling back across privilege scopes.
2. Design and implement authenticated public channel events for project-installed extensions, separate from member-initiated workflows and owner/admin cross-Space worker commands.
3. Continue the Foundry artifact-led authoring and calibration gaps already tracked in `TOKENIZERS-FIRST-IMPLEMENTATION-AUDIT.md` and `FOUNDRY-IMPLEMENTATION-PROGRESS.md`.

Deferred future direction: direct-worker/JeV selection versus planner/worker swarms, subject to the user's later scope deferral. Revisit only when broader swarm work is reactivated.
