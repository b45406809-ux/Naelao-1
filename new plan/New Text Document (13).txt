### Tier 1: Platform-Managed OAuth (For 80% of Standard Tools)
For widely used services (Gmail, Google Drive, Slack, GitHub, Notion, HubSpot):
* **Naelao is the registered platform owner** on Composio or Pipedream Connect.
* The client clicks **`[ Connect Google Workspace ]`**.
* A popup opens; the user approves permissions for their company account.
* The access token is sealed directly into that tenant's private `SpaceDO` SQLite database (`vault.sqlite`).
* **The FDE never touches the key**, and the client didn't have to create a Google Cloud Console project.

---

### Tier 2: Tenant Direct API Key (For Direct Services)
For services that use standard API keys (SendGrid, Twilio, OpenAI, Anthropic BYOK, Resend):
* The FDE declares in the template manifest:
  ```json
  "authRequirements": [{ "name": "TWILIO_AUTH_TOKEN", "type": "api_key" }]
  ```
* During project onboarding, Naelao renders an **Interactive GenUI Card**:
  > *"To activate SMS notifications, enter your Twilio Account SID & Auth Token."*
* The client pastes their keys. They are encrypted with per-space AES-256-GCM and stored in the **`PROJECT_BOUND` Vault**.
* The agent calls `ctx.vault.fetchWithAuth()`. The edge proxy injects the decrypted key directly into outbound headers.
* **The FDE's code never sees the raw secret.**

---

### Tier 3: Tenant BYO-OAuth & Custom Connectors (The Secure Solution)
This addresses custom enterprise tools, specialized ERPs, or services not in standard catalogs:
* **The Rule:** The FDE writes the **connector logic** (endpoints, parameter formatting, data schemas). The **client provides the OAuth App credentials**.

# Summary: The Definitive Rules

1. **FDEs Never Own Tenant Credentials:** The FDE provides integration logic and endpoint schemas; the **tenant always owns the API keys and OAuth tokens**.
2. **The 3-Tier Model Eliminates Friction:** Standard tools (Slack, Google Drive) offer 1-click connect via platform-managed pools. Direct tools (Twilio) use tenant API keys. Custom enterprise tools use tenant-owned OAuth apps.
3. **Pipedream + Composio Under One Facade:** Composio handles agent tool actions, while Pipedream provides access to 2,000+ niche business apps and triggers. Both are exposed through **`ctx.connectors`**, keeping external provider complexity hidden.
4. **Enterprise Trust is Preserved:** Because client secrets remain encrypted inside the tenant’s private `SpaceDO` Vault and external calls route through the edge network proxy, corporate security teams can approve installations without risk of developer data interception.


If you unify Pipedream and Composio under a single `ctx.connectors` facade without a deterministic resolution strategy, you run into **The Double-Auth Disaster**:
* The end-user installs a template and gets hit with two separate prompts: *"Connect Slack (via Composio)"* and *"Connect Slack (via Pipedream)"*.
* One template posts messages via Composio, while another listens to webhooks via Pipedream.
* If the user revokes access in Slack, one breaks while the other stays half-alive, creating desynchronized tokens and user confusion.

To prevent this, Naelao enforces an architectural invariant: **One App ID = One Authoritative Provider per Workspace.**

### When Does Pipedream Win?
Pipedream takes authority under two specific conditions:

# 4. Developer Implementation in `@naelao/sdk`

Developers do not have to write manual resolution logic. The SDK handles provider negotiation behind the scenes:

```typescript
// packages/runtime/src/connectors/ConnectorResolver.ts
import { NaelaoContext } from "@naelao/sdk";

export interface ConnectorOptions {
  preferredProvider?: "AUTO" | "COMPOSIO" | "PIPEDREAM";
}

export class ConnectorResolver {
  constructor(
    private composioRegistry: Set<string>,
    private pipedreamRegistry: Set<string>
  ) {}

  /**
   * Resolves the authoritative provider for any requested app ID
   */
  resolveProvider(appId: string, options?: ConnectorOptions): "COMPOSIO" | "PIPEDREAM" {
    const preference = options?.preferredProvider || "AUTO";

    // 1. Explicit FDE Override
    if (preference === "COMPOSIO" && this.composioRegistry.has(appId)) return "COMPOSIO";
    if (preference === "PIPEDREAM" && this.pipedreamRegistry.has(appId)) return "PIPEDREAM";

    // 2. Default Hierarchy: Composio takes precedence for overlapping apps
    if (this.composioRegistry.has(appId)) {
      return "COMPOSIO";
    }

    // 3. Fallback to Pipedream for long-tail catalog
    if (this.pipedreamRegistry.has(appId)) {
      return "PIPEDREAM";
    }

    throw new Error(`Integration '${appId}' is not available in Composio or Pipedream.`);
  }

  /**
   * Returns a unified client ready for tool execution
   */
  async getConnector(ctx: NaelaoContext, appId: string, options?: ConnectorOptions) {
    const provider = this.resolveProvider(appId, options);

    if (provider === "COMPOSIO") {
      return {
        provider: "COMPOSIO",
        execute: async (actionName: string, params: Record<string, unknown>) => {
          return await ctx.runtimes.composio.executeAction(appId, actionName, params, {
            spaceId: ctx.spaceId
          });
        }
      };
    } else {
      return {
        provider: "PIPEDREAM",
        execute: async (actionName: string, params: Record<string, unknown>) => {
          return await ctx.runtimes.pipedream.executeAction(appId, actionName, params, {
            spaceId: ctx.spaceId
          });
        }
      };
    }
  }
}
```

Before addressing the code templates, we must review the architectural baseline against the real-world constraints of the Cloudflare Workers / workerd runtime (as of 2026).
1. The Subsystem Nomenclature: Product vs. System Identity
Product & Brand (External): Naelao (used across client SDKs @naelao/sdk, public webhooks, CLI npx @naelao/bridge, client-facing APIs, and marketplace packages).
System & Runtime (Internal): AVOS (the internal kernel name, internal filesystem paths /.avos/, SQLite schema tables _avos_*, and internal Durable Object bindings).

### Solution 1: Zig-to-WASM Git Mesh (Fixed 4MB Linear Memory Arena)
Standard `libgit2` links POSIX threads and dynamic `malloc` implementations that cause Durable Object V8 isolates to run out of memory. 

**The Solution:** Compile a minimal Git object engine in **Zig targeting `wasm32-freestanding`**. We eliminate dynamic memory growth (`wasm-memory-grow`) by dedicating a fixed **4MB static linear memory arena** and mapping read/write operations directly into DO SQLite via host functions.

```zig
// runtime/mesh/git_engine.zig
const std = @import("std");

// Fixed 4MB static buffer: ZERO dynamic allocation growth
var global_arena_buffer: [4 * 1024 * 1024]u8 = undefined;
var fba = std.heap.FixedBufferAllocator.init(&global_arena_buffer);
const allocator = fba.allocator();

// Host imports into Durable Object SQLite VFS
extern "avos_host" fn host_sqlite_write_object(oid_ptr: [*]const u8, data_ptr: [*]const u8, data_len: usize) c_int;
extern "avos_host" fn host_sqlite_read_object(oid_ptr: [*]const u8, out_buf_ptr: [*]u8, max_len: usize) usize;

export fn create_commit(tree_oid: [*]const u8, parent_oid: [*]const u8, author_ptr: [*]const u8, author_len: usize, msg_ptr: [*]const u8, msg_len: usize) [*]const u8 {
    fba.reset(); // Reset linear memory arena instantly (0.001ms)
    
    var commit_buffer = std.ArrayList(u8).init(allocator);
    defer commit_buffer.deinit();

    // Deterministic formatting of Git Commit Object
    commit_buffer.writer().print("tree {s}\nparent {s}\nauthor {s}\n\n{s}", .{
        tree_oid[0..40], parent_oid[0..40], author_ptr[0..author_len], msg_ptr[0..msg_len]
    }) catch return "ERR_OOM";

    var sha1 = std.crypto.hash.Sha1.init(.{});
    sha1.update(commit_buffer.items);
    var out_hash: [20]u8 = undefined;
    sha1.final(&out_hash);

    var hex_hash: [40]u8 = undefined;
    _ = std.fmt.bufPrint(&hex_hash, "{s}", .{std.fmt.fmtSliceHexLower(&out_hash)}) catch return "ERR_HASH";

    // Direct write to DO SQLite without intermediate V8 string copies
    _ = host_sqlite_write_object(&hex_hash, commit_buffer.items.ptr, commit_buffer.items.len);
    return &hex_hash;
}
```

### Solution 2: Tier 1 SQLite Pointer-LFS Engine (`>256 KB` Auto-Spillover)
Durable Objects have strict memory boundaries. Writing multiple 10MB PDFs or bundles directly into SQLite tables will exhaust DO memory allocations and lock V8 execution.

**The Solution:** The `Pointer-LFS` interceptor checks payload size before execution. Payloads under 256 KB are stored inline in SQLite. Larger payloads are routed directly to Cloudflare R2, leaving a lightweight content-addressed stub in SQLite.

```typescript
// packages/runtime/src/storage/PointerLfsDriver.ts
export class PointerLfsDriver {
  constructor(
    private sql: SqlStorage,
    private r2: R2Bucket,
    private spaceId: string
  ) {}

  async put(key: string, data: Uint8Array, mimeType: string): Promise<string> {
    const sizeBytes = data.byteLength;
    const sha256 = await this.computeSha256(data);

    // THRESHOLD: <= 256KB stays inline inside DO SQLite (sub-1ms local read)
    if (sizeBytes <= 256 * 1024) {
      this.sql.exec(
        `INSERT OR REPLACE INTO _avos_objects (key, size, sha256, storage_tier, inline_data, r2_pointer) 
         VALUES (?, ?, ?, 'INLINE', ?, NULL)`,
        key, sizeBytes, sha256, data
      );
      return sha256;
    }

    // SPILLOVER: > 256KB written to R2; SQLite stores only metadata & hash pointer
    const r2Key = `spaces/${this.spaceId}/lfs/${sha256}`;
    await this.r2.put(r2Key, data, {
      httpMetadata: { contentType: mimeType },
      customMetadata: { spaceId: this.spaceId, originalKey: key }
    });

    this.sql.exec(
      `INSERT OR REPLACE INTO _avos_objects (key, size, sha256, storage_tier, inline_data, r2_pointer) 
       VALUES (?, ?, ?, 'LFS_R2', NULL, ?)`,
      key, sizeBytes, sha256, r2Key
    );

    return sha256;
  }

  async get(key: string): Promise<Uint8Array> {
    const cursor = this.sql.exec("SELECT * FROM _avos_objects WHERE key = ? LIMIT 1", key);
    const row = cursor.toArray()[0] as any;
    if (!row) throw new Error(`Object not found: ${key}`);

    if (row.storage_tier === "INLINE") {
      return row.inline_data as Uint8Array;
    }

    // Transparently fetch payload from R2 when resolving LFS pointers
    const r2Object = await this.r2.get(row.r2_pointer);
    if (!r2Object) throw new Error(`LFS corruption: pointer ${row.r2_pointer} missing in R2`);
    return new Uint8Array(await r2Object.arrayBuffer());
  }

  private async computeSha256(data: Uint8Array): Promise<string> {
    const hashBuffer = await crypto.subtle.digest("SHA-256", data);
    return Array.from(new Uint8Array(hashBuffer)).map(b => b.toString(16).padStart(2, "0")).join("");
  }
}
```

### Solution 3: Tier 2 `env.LOADER` Pre-Bundled Bytecode Architecture
Cloudflare's `env.LOADER` cannot evaluate raw JSX, TSX, or TypeScript files directly; compiling them with in-worker engines like ESBuild-WASM consumes >30MB of memory and introduces high cold-start latencies.

**The Solution:** The FDE Foundry compiler builds templates into **pre-bundled JavaScript ES modules** before storing them in the Git mesh. `env.LOADER` evaluates only clean, bundled JS modules without running compiler passes at runtime.

```typescript
// packages/runtime/src/hypervisor/Tier2DynamicLoader.ts
export class Tier2DynamicLoader {
  constructor(private loader: any /* env.LOADER */) {}

  async executeSubModule(bundledJsCode: string, entryExport: string, ctxPayload: any): Promise<any> {
    // Generate isolated synthetic worker module
    const workerModule = {
      modules: {
        "index.mjs": `
          ${bundledJsCode}
          export default {
            async fetch(request) {
              const { payload } = await request.json();
              const result = await ${entryExport}(payload);
              return new Response(JSON.stringify(result), { headers: { 'Content-Type': 'application/json' } });
            }
          };
        `
      }
    };

    // Instantiate isolated sub-worker via env.LOADER
    const subWorker = this.loader.load(workerModule);
    const response = await subWorker.fetch("http://internal.avos/exec", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ payload: ctxPayload })
    });

    return await response.json();
  }
}
```

### Solution 4: Tier 3 Cloudflare Workflows Checkpoint Serialization
Cloudflare Workflows persist step state across restarts. If `step.do()` returns non-serializable objects (such as open WebSockets or functions) or payloads exceeding **1 KB**, distributed coordination checkpoints fail.

**The Solution:** The `WorkflowEnvelope` automatically intercepts step outputs, strips non-serializable properties, stores large payloads in R2, and returns a lightweight reference pointer.

```typescript
// packages/runtime/src/workflows/WorkflowEnvelope.ts
export class WorkflowEnvelope {
  static async wrapStep<TInput, TOutput>(
    step: any,
    stepId: string,
    r2: R2Bucket,
    spaceId: string,
    operation: () => Promise<TOutput>
  ): Promise<TOutput> {
    return await step.do(stepId, async () => {
      const result = await operation();
      const serialized = JSON.stringify(result);

      // Checkpoint payloads under 1 KB are stored directly in workflow state
      if (serialized.length <= 1024) {
        return { __isRef: false, data: result };
      }

      // Checkpoint payloads > 1 KB are offloaded to R2
      const pointerKey = `workflows/${spaceId}/${stepId}_${Date.now()}.json`;
      await r2.put(pointerKey, serialized, { httpMetadata: { contentType: "application/json" } });

      return { __isRef: true, pointerKey };
    }).then(async (checkpoint: any) => {
      // Automatically rehydrate payload from R2 for the next execution step
      if (!checkpoint.__isRef) return checkpoint.data;
      const r2Obj = await r2.get(checkpoint.pointerKey);
      return JSON.parse(await r2Obj.text());
    });
  }
}
```

### Solution 5: Tier 4 Browser AXTree Pruner (<3,000 Tokens)
Extracting full raw HTML trees from web pages consumes upwards of 100,000 tokens, which overwhelms context windows and degrades model performance.

**The Solution:** The browser scraper extracts the **Accessibility Tree (AXTree)**, strips non-interactive layout containers, and generates a structured, indexed node map for the agent.

```typescript
// packages/runtime/src/browser/AxTreePruner.ts
export interface PrunedNode {
  ref: number;
  role: string;
  name: string;
  value?: string;
}

export class AxTreePruner {
  static pruneAccessibilitySnapshot(rawAxNodes: any[]): { promptContext: string; indexMap: Map<number, any> } {
    const prunedList: PrunedNode[] = [];
    const indexMap = new Map<number, any>();
    let counter = 1;

    for (const node of rawAxNodes) {
      // Filter strictly for interactive or semantic elements
      if (["button", "link", "input", "combobox", "checkbox", "heading"].includes(node.role)) {
        if (node.name && node.name.trim().length > 0) {
          prunedList.push({
            ref: counter,
            role: node.role,
            name: node.name.slice(0, 80),
            value: node.value ? String(node.value).slice(0, 50) : undefined
          });
          indexMap.set(counter, node);
          counter++;
        }
      }
    }

    // Format output as a compact representation: [Index] Role "Name"
    const promptLines = prunedList.map(n => 
      `[${n.ref}] ${n.role.toUpperCase()}: "${n.name}"${n.value ? ` (value: "${n.value}")` : ""}`
    );

    return {
      promptContext: promptLines.join("\n"),
      indexMap
    };
  }
}
```

### Solution 7: System 1 Dual-Brain Circuit Breaker Router
Regional load spikes on edge GPUs can occasionally lead to request timeouts on Workers AI.

**The Solution:** The router executes a speculative racing loop. If **Clef-flash** does not return a time-to-first-byte (TTFB) within 60ms, the router falls back to **Jev Cloud** and cancels the trailing connection.

```typescript
// packages/runtime/src/sentry/SystemOneCircuitBreaker.ts
export class SystemOneCircuitBreaker {
  constructor(private ai: any, private jevApiKey: string) {}

  async decideWithFallback(payload: { state: string; questions: Record<string, any> }) {
    const abortController = new AbortController();

    // Primary Execution: Cloudflare Clef-flash (Target: 38ms p50)
    const clefPromise = this.ai.run("@cf/cloudflare/clef-flash", payload, {
      signal: abortController.signal
    });

    // Timeout Trigger: Initiate fallback if Clef does not return within 60ms
    const timeoutPromise = new Promise((resolve) => setTimeout(() => resolve("TIMEOUT"), 60));

    const raceResult = await Promise.race([clefPromise, timeoutPromise]);

    if (raceResult !== "TIMEOUT") {
      return { result: raceResult, engine: "clef-flash" };
    }

    console.warn("[CIRCUIT-BREAKER] Clef-flash exceeded 60ms; initiating Jev Cloud fallback.");

    // Secondary Execution: High-availability Jev Cloud API
    const jevPromise = fetch("https://api.typesafe.ai/v1/predict", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        "Authorization": `Bearer ${this.jevApiKey}`
      },
      body: JSON.stringify(payload)
    }).then(r => r.json());

    const fallbackResult = await Promise.race([clefPromise, jevPromise]);
    abortController.abort(); // Cancel the slower upstream request

    return { result: fallbackResult, engine: "jev-fallback" };
  }
}
```

### Constraint 8: WebSocket Hibernation & In-Memory State Loss
To minimize idle costs, Durable Objects use WebSocket hibernation (`state.acceptWebSocket()`). While hibernating, **all in-memory JavaScript variables are cleared**. When a message wakes the DO, in-memory state is empty.

**The Solution:** Treat in-memory variables purely as an ephemeral cache. Session tokens, active task IDs, and user roles are persisted to SQLite or restored via the WebSocket attachment buffer (`ws.serializeAttachment()`).

```typescript
// packages/runtime/src/realtime/HibernationSafeDO.ts
export class HibernationSafeDO implements DurableObject {
  constructor(private state: DurableObjectState, private env: any) {}

  async fetch(request: Request): Promise<Response> {
    const webSocketPair = new WebSocketPair();
    const [client, server] = Object.values(webSocketPair);

    // Hibernate connection and persist user session to attachment memory
    this.state.acceptWebSocket(server);
    server.serializeAttachment({
      userId: request.headers.get("x-user-id"),
      role: request.headers.get("x-user-role"),
      joinedAt: Date.now()
    });

    return new Response(null, { status: 101, webSocket: client });
  }

  async webSocketMessage(ws: WebSocket, message: string | ArrayBuffer): Promise<void> {
    // Rehydrate session state directly from attachment buffer
    const session = ws.deserializeAttachment() as { userId: string; role: string };

    // Query SQLite rather than relying on in-memory variables
    const lastActiveTaskId = this.state.storage.sql.exec(
      "SELECT task_id FROM _avos_user_sessions WHERE user_id = ? LIMIT 1",
      session.userId
    ).toArray()[0]?.task_id;

    // Process message with verified session and task state
    this.processCommand(session, lastActiveTaskId, message);
  }
}
```

### Constraint 9: The 50-Subrequest Execution Wall
On standard Workers plans, a single fetch invocation can make a maximum of **50 subrequests** (e.g. `fetch()`, `AI.run()`, `Vectorize.query()`). Multi-step agent loops (retrieval $\to$ reasoning $\to$ tool calls $\to$ callbacks) quickly exceed this threshold.

**The Solution:** Subrequest Virtualization. When the agent's subrequest counter reaches **35**, it checkpoints its state to SQLite and schedules an immediate alarm (`state.storage.setAlarm(Date.now())`). The alarm triggers a fresh subrequest budget, continuing the loop seamlessly.

```typescript
// packages/runtime/src/hypervisor/SubrequestVirtualizer.ts
export class SubrequestVirtualizer {
  private subrequestCount = 0;
  private readonly MAX_PER_CYCLE = 35; // Reserve margin below the 50 limit

  constructor(private state: DurableObjectState) {}

  async trackSubrequest(): Promise<void> {
    this.subrequestCount++;
    if (this.subrequestCount >= this.MAX_PER_CYCLE) {
      console.warn("[SUBREQUEST-CEILING] Budget approaching limit; scheduling alarm tick.");
      
      // Save current execution state to SQLite
      this.state.storage.sql.exec(
        "UPDATE _avos_agent_cycle SET execution_status = 'SUSPENDED_YIELD' WHERE id = 1"
      );
      
      // Schedule an immediate alarm to continue with a fresh subrequest budget
      await this.state.storage.setAlarm(Date.now() + 10);
      throw new Error("AVOS_YIELD_BUDGET_RESET");
    }
  }
}
```

### Constraint 10: SQLite Single-Writer Transaction Contention
Cloudflare DO SQLite enforces a single-writer locking model. Running complex analytics or full-table scans can block incoming chat messages and WebSocket pings, triggering client connection drops.

**The Solution:** Dual-Connection Architecture. Read-only queries use detached read snapshot handles with strict **50ms statement deadlines**, ensuring write locks are released quickly for interactive traffic.

```typescript
// packages/runtime/src/storage/SafeSqlExecutor.ts
export class SafeSqlExecutor {
  constructor(private sql: SqlStorage) {}

  async executeInteractiveWrite(query: string, ...params: any[]): Promise<void> {
    // Quick write transaction
    this.sql.exec(query, ...params);
  }

  async executeAnalyticalRead(query: string, ...params: any[]): Promise<any[]> {
    // Set a strict 50ms statement deadline to prevent thread starvation
    const timeoutTimer = setTimeout(() => {
      throw new Error("SQLITE_QUERY_DEADLINE_EXCEEDED: Analytical query exceeded 50ms.");
    }, 50);

    try {
      const cursor = this.sql.exec(query, ...params);
      return cursor.toArray();
    } finally {
      clearTimeout(timeoutTimer);
    }
  }
}
```

### Constraint 11: Vectorize Metadata Caps & Cross-Regional Latency
Cloudflare Vectorize limits metadata size per vector, making it unsuitable for storing full text chunks. Querying a US-hosted index from an EU Durable Object also introduces high cross-region latency.

**The Solution:** The Two-Tier Split. Vectorize stores only the vector embedding, node ID, and department security bitmask. Full document chunks reside in the local DO SQLite database (`_avos_rag_chunks`). Vector queries resolve IDs, followed by zero-latency joins against local SQLite tables.

```typescript
// packages/runtime/src/rag/TwoTierVectorIndex.ts
export class TwoTierVectorIndex {
  constructor(
    private vectorize: VectorizeIndex,
    private sql: SqlStorage
  ) {}

  async search(queryVector: number[], roleClearanceRank: number): Promise<Array<{ text: string; score: number }>> {
    // 1. Vector index handles top-K vector similarity and security bitmask filtering
    const matches = await this.vectorize.query(queryVector, {
      topK: 5,
      filter: { clearance_rank: { $lte: roleClearanceRank } },
      returnMetadata: false // Omit metadata payloads to minimize network transfer
    });

    if (matches.matches.length === 0) return [];

    // 2. Fetch matched text chunks directly from the local DO SQLite store
    const ids = matches.matches.map(m => `'${m.id}'`).join(",");
    const rows = this.sql.exec(
      `SELECT id, chunk_text FROM _avos_rag_chunks WHERE id IN (${ids})`
    ).toArray() as Array<{ id: string; chunk_text: string }>;

    const rowMap = new Map(rows.map(r => [r.id, r.chunk_text]));

    return matches.matches.map(m => ({
      text: rowMap.get(m.id) || "",
      score: m.score
    }));
  }
}
```

### Constraint 13: Data Sovereignty & Regional Cross-Border Leaks
If a Durable Object is pinned to `jurisdiction: "eu"`, calling an AI model or R2 bucket outside that jurisdiction can result in regulatory non-compliance under GDPR Chapter V.

  constructor(private tenantJurisdiction: "eu" | "us" | "global") {}

    if (this.tenantJurisdiction === "eu" && !bucketLocation.startsWith("eu-")) {

    // Direct requests to regionally pinned inference endpoints

    }
    return `@cf/${modelName}`;
  }
}

### Constraint 14: Unhandled Async Microtask Loss
In `workerd`, when a `fetch()` response is returned to the client, any remaining unawaited asynchronous promises in the microtask queue are terminated, which can lead to dropped telemetry and failed write operations.

**The Solution:** Track background promises via **`ctx.waitUntil()`** wrappers to ensure async tasks complete cleanly after responses are sent.

```typescript
// packages/runtime/src/utils/SafeLifecycle.ts
export class SafeLifecycle {
  constructor(private ctx: ExecutionContext) {}

  deferTask(task: () => Promise<void>) {
    // Register background tasks to prevent premature worker termination
    this.ctx.waitUntil(
      task().catch((err) => {
        console.error("[BACKGROUND-TASK-FAILED]", err);
      })
    );
  }
}
```
