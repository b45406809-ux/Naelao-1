## External claim checks (primary sources)

- Cloudflare Email Service FAQ, updated October 15, 2026: transactional-only use; [official FAQ](https://developers.cloudflare.com/email-service/reference/faq/).
- Cloudflare Email Service product docs: inbound routing and transactional outbound; arbitrary recipient sending requires Workers Paid; [official product docs](https://developers.cloudflare.com/email-service/).
- Cloudflare's November 4, 2026 site-operator feature provides visibility into supported personal-agent traffic and per-agent access policies. This is traffic visibility/control, not cryptographic AgentPort identity or account-creation authorization; [official Cloudflare post](https://blog.cloudflare.com/personal-agents-visibility-control/).
- MCP maintainers' release announcement for the latest checked spec, July 28, 2026: date-based revision `2026-07-28`, stateless protocol core; [official release](https://blog.modelcontextprotocol.io/posts/2026-07-28/).
- Coinbase official CDP docs describe programmatic server wallet account management and x402 MCP/payment discovery: [server wallet account management](https://docs.cdp.coinbase.com/server-wallets/v2/using-the-wallet-api/managing-accounts), [x402 MCP Bazaar](https://docs.cdp.coinbase.com/api-reference/v2/rest-api/x402-facilitator/bazaar-mcp-server).
- Stripe official product material supports agentic commerce and Shared Payment Tokens. It does not establish automatic issuance of agent-tagged API keys or general AgentPort resale rights: [agentic commerce guide](https://stripe.com/resources/more/agentic-commerce), [Stripe MPP announcement](https://stripe.com/blog/machine-payments-protocol).
- Amazon's official SP-API pages describe application registration and seller authorization. They do not evidence AgentPort permission to create agent seller accounts; no such capability is implemented: [SP-API registration](https://developer-docs.amazon.com/sp-api/lang-en_EN/docs/sp-api-registration-overview), [seller authorization](https://developer-docs.amazon.com/sp-api/lang-US/docs/learn-how-sellers-authorize-service-providers).
- Claims about Singapore policy discussions, Composio token export and Grok browser implementation were not required for this code change and were not used as implementation facts.

## Conflicts and decisions

- Early assistant sketches proposed building many connectors, an A2A layer, a universal payment layer, a single wake/session strategy, and pricing examples. Later user refinements narrowed AgentPort to a provider registry/control plane and made session policy a runtime decision; those later corrections govern.
- User said “MCP v2.” The transcript itself corrects this to supporting the latest standard protocol release/version negotiation rather than inventing an incompatible protocol. This change does not claim MCP v2 support.
- Cloudflare supplies email transport only within its permitted transactional scope. It does not by itself supply an AgentMail-style product, a mailbox protocol, or permission to resell a multi-tenant service. No unapproved marketing route was added.
- The repository's `AGENTS.md` concerns an unrelated previous mission. The user's explicit instruction names this conversation as the governing source, so that stale mission was not applied.

## Known remaining gaps / external blockers

The implemented change is a safe first AgentPort control-plane slice, not the full product described in the transcript. Mailbox/message APIs, independent AgentPort authentication and tenant onboarding, public external API, SDK/CLI/MCP surfaces, credential vault, signed portable KYA/mandates, owner-channel verification and step-up approval, interaction/action firewall, budget engine, provider execution/provisioning, provider webhook/poll adapters, runtime notification delivery, observability UI, usage billing, and local/self-hosted institution verification remain open. The service registry describes capabilities and account models but does not itself invoke providers. Live Cloudflare inbound/outbound operation is blocked on provisioned and approved domain/account configuration; the repository currently has empty ingress/sender-domain values. These are not claimed as completed or live-verified.
