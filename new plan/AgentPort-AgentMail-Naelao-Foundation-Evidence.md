Date: 2026-11-06. Scope is the latest accepted plan in this conversation: AgentPort is the standalone identity/access/event product; AgentMail is the email provider; Naelao is one client/runtime. The earlier proposal to build a separate Naelao-branded AgentMail competitor is superseded by the later plan to measure demand before revisiting standalone Naelao Mail.

## Primary provider documentation reviewed

Current AgentMail docs were fetched from `https://docs.agentmail.to/llms.txt` and the linked primary pages for permissions, multi-tenancy, API key creation, webhooks, events, verification, inboxes, messages, threads, drafts and attachments. AgentMail supports Pods, inbox-scoped API keys and permission whitelists; these are the supported basis for managed tenant separation and BYO credentials. Its API exposes provider-owned read/search/thread/attachment and send operations, and Svix-signed webhooks. AgentMail webhook payloads may contain message content; this integration intentionally discards content after extracting event references.

The AgentMail docs now explicitly describe `inbox_id` scoped keys and a permission whitelist. The UI asks for an inbox-scoped key; the customer must create and rotate that key in AgentMail. No AgentMail secret is stored in AgentPort. AgentMail's documentation states restrictions on outbound use and account verification; managed production onboarding must follow the account's actual sending quota, acceptable-use policy, verified-domain and Pod plan. This implementation does not claim Cloudflare Email Routing supplies mailbox read access and does not use Cloudflare as the mailbox for this plan.

## Conflicts and decisions

- The user's later decision to integrate AgentMail and measure actual demand supersedes earlier discussion of implementing a standalone Naelao Mail clone. No competing mailbox service is being created here.
- The user's provider-neutral corrections supersede any proposal to put message bodies in AgentPort or automatically inject email content into a Naelao session. The event carries references; Naelao may decide whether to invoke authorized provider tools.
- AgentPort is not allowed to impose Naelao's session model. Naelao's event receiver owns wake/session selection; external AgentPort clients may poll, claim, or deliver to their own runtime.
- Existing AgentPort migration 0171 handles generic signed event notifications. Migration 0172 adds only Naelao's AgentMail connection, billing-operation, dedup and wake-outbox metadata.
