# Cloudflare Agents feature extensions

Reviewed 2026-10-15 against Cloudflare's published Agents documentation and the pinned `agents@0.28.1` package. The Agents voice API is marked experimental upstream, so the package version is pinned. This review favors the Cloudflare primitives where they fit and keeps Naelao's existing tenancy, planner, channel, and policy boundaries.

| Cloudflare feature | Naelao integration |
| --- | --- |
| [Voice Agents](https://developers.cloudflare.com/agents/communication-channels/voice/) | Owner browser calls use Cloudflare's `withVoice`, Workers AI STT/TTS, and `VoiceClient`. Each short-lived ticket is owner/admin-only and bound to a Space, session, optional project, and one DO instance. Every spoken turn goes through the existing planner session. Cloudflare voice is denied for air-gapped Spaces. Existing customer telephony remains a separate channel path. The SDK's ordinary WebSocket transport does not require a separate SFU; its SFU transport remains available if a future call contract needs it. |
| [Email](https://developers.cloudflare.com/agents/communication-channels/email/) | Agent `email.provision` creates stable per-agent Cloudflare Email Routing aliases when an ingress domain is configured. Outbound sends prefer Cloudflare Email Service when its binding and verified domain are configured. Task-specific reply aliases and attachments retain their current task checks. AgentMail remains an optional fallback, not a requirement. Mailbox messages currently accept text only; task-reply addresses retain bounded attachment handling. |
| [Slack](https://developers.cloudflare.com/agents/communication-channels/slack/) | Keep the existing OAuth install, request-signature validation, per-Space credentials, channel/thread mapping, and planner handoff. The Cloudflare sample does not replace these tenant and business membership checks. |
| [Webhooks](https://developers.cloudflare.com/agents/communication-channels/webhooks/) | Keep Naelao's normalized webhook envelope, per-Space secret vault, signature verification, deduplication, URL/egress policy, and durable planner wake-up. Add provider-specific adapters through this boundary rather than a second generic webhook runtime. |
| [Push notifications](https://developers.cloudflare.com/agents/communication-channels/webhooks/push-notifications/) | Browser Web Push now uses the existing Notifications Worker and tenant/user-scoped subscriptions. The Shell enrolls/removes the current member's browser endpoint through the Spaces membership gate; endpoints and key material are encrypted at rest, provider hosts are allow-listed, expired endpoints are pruned, and Space egress policy is checked before delivery. Existing APNs/FCM paths remain separate. |
| [Autonomous responses](https://developers.cloudflare.com/agents/communication-channels/chat/autonomous-responses/) | Naelao already has durable queues/workflows and planner controls. Continue using those for long-running work; don't duplicate execution or expose unsupervised tool actions from a channel callback. |
| [Client SDK](https://developers.cloudflare.com/agents/communication-channels/chat/client-sdk/) | Naelao's custom chat client preserves product-session credentials, polling/stream replay, approvals, questions, and thread parity. The voice feature reuses Cloudflare's framework-agnostic voice client without replacing that chat surface. A wholesale client-SDK swap is not justified. |
| [MCP Code Mode](https://developers.cloudflare.com/agents/model-context-protocol/codemode/) | Naelao already has a constrained code-execution tier and MCP capability boundaries. Cloudflare Code Mode is an implementation option for the MCP host, not authorization to bypass Naelao's model, file, egress, or approval checks. |

## Operator prerequisites

For inbound per-agent mail, set `EMAIL_INGRESS_DOMAIN`, configure the domain's Cloudflare Email Routing Worker action to the Agents Worker, and apply `infra/migrations/0094_agent_email_addresses.sql`. For outbound mail, separately onboard a sender domain to Cloudflare Email Service and set `EMAIL_SENDING_DOMAIN`. Browser push requires a VAPID public/private key pair, `WEB_PUSH_VAPID_SUBJECT`, and migration `infra/migrations/0095_web_push_subscriptions.sql`. These are distinct Cloudflare services; local tests do not prove DNS, domain ownership, provider delivery, or live routing.

## Evidence limits

The voice implementation is typechecked and Wrangler dry-run built, but no live Cloudflare AI, microphone/WebSocket, SFU, or account test was run. Email route behavior is locally tested with mocked bindings and D1; Cloudflare account configuration and deliverability remain unverified. Web Push protocol, encryption, tenant token gate, and queue cleanup are locally tested with mocked push services; a real browser/provider delivery still requires VAPID configuration and deployed migration. Cloudflare's MCP Code Mode docs do not establish that it replaces the existing isolated code runner.
