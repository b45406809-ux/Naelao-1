# Requirements-to-code trace matrix (build-plan items 1–87)

## Reading and precedence

This matrix starts at `_BUILD_PLAN/plan.md` item 1 and contains exactly 87 numbered requirement rows. For every row, the complete `Origin & Transition` trail was read left-to-right. JSON references mean the relevant zero-based `chunkedPrompt.chunks[].text` entry was read in array order; the unnumbered Master Blueprint reference means its final consolidated response was read. The reconciliation order is: origin trail → Master Blueprint → `CLAUDE.md` → canonical `naelao_expanded_gaps_resolved.html` → Appendix A1. Later material wins unless this repository's current explicit product direction says otherwise.

The important reconciliations are:

* “Two level” means **depth 0 root plus depth 1 department**, not two levels below a root. Appendix A1’s occasional “depth ≤ 2” prose is superseded by its own later single-hop rule and the canonical product hierarchy.
* The blueprint’s conceptual six-rung compute ladder remains observable as VFS, isolate, durable workflow, Kitesurf, Chromium, and container. Appendix A1’s production `requires_tier` values deliberately number only capability ceilings 1–5: workflow is orthogonal (`runtime: workflow`) and Kitesurf/Chromium are two engines behind the browser ceiling. The model never selects either representation directly.
* Appendix A1’s script-first six-operation control plane supersedes the early three-tool prompt sketch. `script.run` is the one invisible execution router; full catalogs and credentials are not put in prompts.
* “FUSE” is implemented as lazy ArtifactFS/R2 materialization because Workers Containers do not expose a deployable custom FUSE kernel contract. Observable semantics—metadata-first listing, read-on-demand, and write-back—are authoritative.
* `/.avos/` denotes control state and `/workspace/` deliverables. In object storage these are separate prefixes; in containers they are separate absolute roots. Crossing from one root to the other via `..` is rejected rather than normalized.
* Item 54's Master Blueprint says to drop Pipedream, but all three later authorities explicitly retain and complete it (`CLAUDE.md` items 56–57, expanded gaps BF.1/BF.2, and Appendix A1 phase P). Therefore Composio is the default managed broker and Pipedream remains a supported secondary broker; deleting it would violate the repository's later product decision.
* A helper, type, comment, mocked unit, or empty shell is **not** end-to-end evidence. `IMPLEMENTED` below means a request crosses a real production entry point and scoped persistence/bindings; `PARTIAL` names the missing boundary; `MISSING` means no production path was found.
