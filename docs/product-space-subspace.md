# Product, Space and subspace

Naelao's hierarchy is **Product → end-user Space → subspace**. Launchpad is one Product shared by all users. Each user creates Spaces; each Space owns projects and may contain logical subspaces inside its SpaceDO. A subspace has its own membership checks and assistant identity. It is not a separate D1 tenant or independently isolated Durable Object.

Generic Space creation does not derive a Product slug or create a Product. Launchpad bootstrap writes the platform Product to the `products` registry. New customer Spaces are root rows with an explicit `spaces.product_id`, no Product parent, and an owner membership committed with the row.

## Registry cutover

Migration `0156_product_registry.sql` preserves Product IDs and copies names, slugs, status and configuration into `products`. Migration `0157_product_registry_cutover.sql` drops the synchronization triggers, converts only consistent same-tenant Product parent links to direct `product_id` references, and cancels pending provisioner intents for compatibility rows. The provisioner rejects already-delivered messages for those Product IDs. Product rows remain as inert compatibility data; runtime bootstrap, auth, session verification, shell lookup, branding, model policy, credentials, admin suspension, erasure and account Space authorization use the registry and direct links.

The cutover migration records contradictory or incomplete links in `product_link_migration_issues`. It retains each original parent and direct Product value. A reference generated by migration 0156 is cleared only when it is demonstrably wrong (a cross-tenant Product parent or a row that is itself another unregistered legacy Product); no account, session, membership, Space ID or Product ID is regenerated. Launchpad bootstrap fails closed if the audit table contains an unresolved legacy Launchpad identity.

Product sessions establish identity only. The Spaces Worker separately resolves active membership in the requested end-user Space; subspace routes enforce the SpaceDO hierarchy and subspace permissions. The Project Bots view can request projects from subspaces the caller may read and deduplicates projects linked to more than one subspace.

## Customer subscriptions and Space limits

Launchpad customer plans are stored by `(product_id, end_user_id)` in `product_user_subscriptions`. Customer checkout uses separate customer plan IDs and its signed subscription webhooks update that row; it never changes or inherits the Naelao team organization's subscription. Space creation counts only Spaces linked to that Product account and applies the current account tier in the conditional D1 insert. The org plan continues to govern ordinary team-created Spaces.

## Verification and rollout

The migration and unit coverage exercises registry backfill, safe upgrade links, conflicting and orphaned relationships, bootstrap identity, Product sessions, shell manifest lookup, Space creation limits, customer subscription lifecycle, Space subspaces, and admin Product suspension. The full GitHub Actions inventory provides the fresh local runtime and browser acceptance suites. A deployed Cloudflare D1 migration and provisioner run is still required before production rollout; existing issue rows must be reviewed and explicitly repaired before their affected accounts can use those Spaces through the new direct Product link.
