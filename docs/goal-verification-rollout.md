# Goal verification rollout

Goal DAG verification is opt-in. The safe default is `GOAL_VERIFICATION_REQUIRED=false`; `GOAL_VERIFICATION_SHADOW_ENABLED=true` records advisory assessments and aggregate comparisons without changing task completion. Do not enable required verification until the deployment has a fresh OpenRouter model card and price for the selected Decisions API model, a working `BILLING_WORKER` connection, and the matching D1 migration (`0152_decision_call_reservations.sql`) applied.

Required mode fails closed unless every task provides one to eight bounded acceptance criteria and explicit host operations such as `workspace.sha256:path`, `artifact.sha256:path`, or `workspace.exists:path`. These specs only read declared files in the worker's authorized branch. Free-form acceptance text and worker statements are never evidence. Paths are bounded to 1 MiB each and 32 artifacts. A missing file, oversized object, concurrent mutation, scope mismatch, stale branch version, or unavailable object leads to review. Evidence references and hashes stay in the private goal journal; project activity receives aggregate counts only.

The decision model receives criteria plus evidence outcomes and bounded references, never file contents. Deterministic evidence is authoritative; model disagreement is review. The default decision policy remains Clef Flash, with the configured approved long-context model only when the request exceeds the short-context limit. Provider attempts are reserved before egress using current catalog pricing; missing price evidence or quota admission blocks the call. Unknown provider outcomes retain their durable reservation as uncertain.

Existing journals are not upgraded. A legacy `completed` task with no verification result remains an unverified completion; when required verification is later enabled, it is rechecked against its current worker attempt, and missing provenance becomes review. Review and uncertain states block dependents. Verification failures do not invoke the worker-failure fixer.

Worker dispatch intent is persisted in the goal journal before the existing worker session is called. Retries reuse the same worker ID and branch. Lost acknowledgements recover that session; an unresolved outcome becomes review instead of a new external action. Resource queues remain authoritative for concurrency.

Shadow rollout comparison is available through aggregate `shadow_review_count`, `shadow_uncertain_count`, and independently determined verification pass/fail/review counts. These values are diagnostic only; they do not establish production quality. Current provider-side lookup/reconciliation for a request that times out after reaching OpenRouter is not available in this repository, so uncertain reservations must remain held until an operator or future trusted reconciliation adapter supplies usage evidence.
