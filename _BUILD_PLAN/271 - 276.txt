# 1. Shared Cross-Project State (The Space-Wide Calendar & Ledger)
While project files are isolated (`spaces/{spaceId}/projects/{projectId}/...`), business facts like **Customer Bookings, Appointments, and Client CRM Records** must be visible across **all projects and agents simultaneously**.
Since **`SpaceDO`** is already the single authoritative state actor for the entire business space, we host the **Universal Shared State Plane** directly inside `SpaceDO`'s SQLite database.
```
                                  ┌──────────────────────────────────────────────┐
                                  │       SPACE-WIDE SHARED STATE (SpaceDO)      │
                                  │      `space_calendar` & `shared_crm_state`   │
                                  └──────────────────────┬───────────────────────┘
                                                         │
         ┌───────────────────────────────────────────────┼───────────────────────────────────────────────┐
         ▼ (Book 3:00 PM Slot)                           ▼ (Read Schedule)                               ▼ (Notify Client)
┌─────────────────────────────────┐             ┌─────────────────────────────────┐             ┌─────────────────────────────────┐
│ 📞 Voice Call / WhatsApp Bot    │             │ ⚖️ Legal / Dev Workstation      │             │ 🏛️ Space Assistant (CEO)       │
│ Project: `customer_bot`         │             │ Project: `doc_studio`           │             │ (Space-Wide Oversight)          │
├─────────────────────────────────┤             ├─────────────────────────────────┤             ├─────────────────────────────────┤
│ Customer calls or texts:        │             │ Lawyer drafts contract:         │             │ Morning Digest via Telegram:    │
│ "Book consultation for Friday." │             │ Sees Alice booked for Friday;   │             │ "You have 3 consultations       │

└─────────────────────────────────┘             └─────────────────────────────────┘             └─────────────────────────────────┘
```

### The Universal `ctx.space.calendar` SDK Method:
Every project agent (Developer, Support, Voice Agent) can query or book slots in **1 turn**:
```typescript
// Any agent can run this inside Tier 2 CodeMode or tool calls:
export async function bookClientAppointment(clientName: string, time: string, ctx: any) {
  // 1. Check for double-booking across the whole business
  const existing = await ctx.space.calendar.checkAvailability(time);
  if (!existing.available) {
    return { ok: false, error: "Slot already booked. Suggest alternate time." };
  }
  // 2. Atomically book slot in SpaceDO
  await ctx.space.calendar.bookSlot({
    clientName,
    startTime: time,
    eventType: "consultation"
  });
  // 3. WsHubDO automatically broadcasts `calendar.booked` to all UI dashboards!
  return { ok: true, message: `Appointment confirmed for ${clientName} at ${time}.` };
}
```

# 3. Native Voice-to-Text in ComposerDock (WhisperFlow Style)
To give users a voice dictation experience (like Claude or WhisperFlow) in the chat bar, **`apps/shell` captures audio directly from the browser microphone and transcribes it at the edge using Workers AI `@cf/openai/whisper` for $0 compute cost.**
```
[ User presses Mic icon 🎙️ in ComposerDock and speaks ]
                          │
                          ▼ (Browser MediaRecorder captures 5s audio chunk)
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. POST /api/voice/transcribe (To Cloudflare Router Worker)                 │
├─────────────────────────────────────────────────────────────────────────────┤
│ 2. RUN WORKERS AI WHISPER MODEL                                             │
│    `const res = await env.AI.run("@cf/openai/whisper", { audio: buffer })` │
├─────────────────────────────────────────────────────────────────────────────┤
│ 3. INSTANT TRANSCRIPTION INSERTION                                          │
│    The transcribed text automatically types into the chat message box!      │
└─────────────────────────────────────────────────────────────────────────────┘
```
### Implementation:
#### A. The Cloudflare Edge Transcription Route (`workers/router/src/index.ts`):
```typescript
// workers/router/src/index.ts
app.post("/v1/voice/transcribe", async (c) => {
  const formData = await c.req.formData();
  const audioFile = formData.get("audio") as File;
  if (!audioFile) return c.json({ error: "No audio payload" }, 400);
  const arrayBuffer = await audioFile.arrayBuffer();
  const audioBytes = [...new Uint8Array(arrayBuffer)];
  // Run Cloudflare's edge-native Whisper model (Included in Workers AI)
  const response = await c.env.AI.run("@cf/openai/whisper", {
    audio: audioBytes
  });
  return c.json({ ok: true, text: response.text });
});
```
#### B. The Microphone Button in `apps/shell/src/components/ComposerDock.tsx`:
```tsx
// Inside ComposerDock.tsx
export function VoiceInputButton({ onTranscribed }: { onTranscribed: (text: string) => void }) {
  const [recording, setRecording] = useState(false);
  const mediaRecorderRef = useRef<MediaRecorder | null>(null);
  const startRecording = async () => {
    const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
    const mediaRecorder = new MediaRecorder(stream);
    const audioChunks: Blob[] = [];
    mediaRecorder.ondataavailable = (e) => audioChunks.push(e.data);
    mediaRecorder.onstop = async () => {
      const audioBlob = new Blob(audioChunks, { type: "audio/webm" });
      const formData = new FormData();
      formData.append("audio", audioBlob);
      // Send to our Cloudflare edge Whisper endpoint
      const res = await fetch("/v1/voice/transcribe", { method: "POST", body: formData });
      const data = await res.json() as any;
      if (data.text) onTranscribed(data.text);
      setRecording(false);
    };
    mediaRecorder.start();
    mediaRecorderRef.current = mediaRecorder;
    setRecording(true);
  };
  const stopRecording = () => {
    mediaRecorderRef.current?.stop();
  };
  return (
    <button
      type="button"
      className={`dock-btn ${recording ? "recording-pulse" : ""}`}
      onClick={recording ? stopRecording : startRecording}
      title={recording ? "Click to stop recording" : "Voice dictation (WhisperFlow)"}
      style={{ color: recording ? "var(--danger, #ef4444)" : "var(--text3)" }}
    >
      🎙️ {recording && <span style={{ fontSize: "11px", marginLeft: "4px" }}>Listening...</span>}
    </button>
  );
}
```

### 4. Hardware-Level Cryptographic Security (Zero Leaks)
The security is not just an advisory prompt instruction; it is **enforced at the Cloudflare Worker credential boundary**:
```typescript
// workers/credentials/src/index.ts (resolveCredential hierarchy)
export async function resolveCredentialForRun(
  spaceId: string,
  connectorName: string,
  runContext: { actingUserId?: string; projectId?: string; isSystemCron?: boolean }
) {
  // RULE 1: System Crons & Heartbeats CANNOT access Personal Credentials
  if (runContext.isSystemCron && !runContext.actingUserId) {
    // Falls back strictly to Space-Shared row (scope = 'space')
    return await fetchSpaceSharedCredential(spaceId, connectorName);
  }
  // RULE 2: Project-Bound Connectors are checked against project_id
  if (runContext.projectId) {
    const projectCred = await fetchProjectBoundCredential(spaceId, runContext.projectId, connectorName);
    if (projectCred) return projectCred;
  }
  // RULE 3: Personal Credentials require exact matching User ID
  if (runContext.actingUserId) {
    const personalCred = await fetchUserPersonalCredential(spaceId, runContext.actingUserId, connectorName);
    if (personalCred) return personalCred;
  }
  // Default fallback: Space-Shared Credential
  return await fetchSpaceSharedCredential(spaceId, connectorName);
}
```

### Summary of What This Solves:
1. **No Shared-Calendar Confusion:** The agent knows that `mcp.company_calendar` updates the **SpaceDO global calendar table** visible to all projects, while `mcp.personal_calendar` only touches the user's private schedule.
2. **Prevents Autonomous Identity Hijacking:** An unattended 2:00 AM background cron cannot accidentally use Alice’s personal Gmail account to email a client, because personal credentials are cryptographically inaccessible without an active `actingUserId` session.
3. **Clean Project Sandboxing:** Customer-facing WhatsApp numbers and Discord bots are bounded to their specific `customer_bot` projects, keeping company-wide and personal communication channels completely separated.
