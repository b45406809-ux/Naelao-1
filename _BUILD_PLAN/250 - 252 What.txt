### 2. The "Gatekeepers" Capability-Based Security Model
The fatal flaw of traditional plugins and AI-generated apps is **Raw API Keys**:
* If an AI micro-app is given a master API key, a malicious prompt or buggy script can query other departments, read executive emails, or drain company funds.
**Gatekeepers replaces API keys with Unforgeable, Attenuated Capability Tokens.**
```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    THE GATEKEEPER SECURITY PROTOCOL                         │
├─────────────────────────────────────────────────────────────────────────────┤
│ 1. THE HUMAN PERMISSION CEILING (Invariant #1)                              │
│    An agent or micro-app can NEVER hold more power than the human who       │
│    created it. If Alice is a "Member" (no refund authority), any micro-app  │
│    Alice builds is physically incapable of minting refund capabilities.     │
├─────────────────────────────────────────────────────────────────────────────┤
│ 2. RESOURCE-LEVEL ATTENUATION (Invariant #2)                                │
│    The micro-app is issued a cryptographically signed Gatekeeper Token:     │
│    • `db:access` ──► Restricted strictly to its own SQLite table.          │
│    • `slack:post` ──► Restricted to `#warehouse-alerts` (Max 10 msgs/day).  │
│    • `stripe:charge` ──► BLOCKED.                                           │
├─────────────────────────────────────────────────────────────────────────────┤
│ 3. ZERO-LEAK RUNTIME PROXY (Invariant #3)                                   │
│    The micro-app code NEVER holds secrets. Outbound requests pass through   │
│    the Gatekeeper Proxy, which verifies the token before injecting secrets  │
│    at the edge network boundary.                                            │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3. How Gatekeepers Works in Code
#### A. The Gatekeeper Capability Token Definition
```typescript
// packages/security/src/gatekeeper.ts
export interface GatekeeperCapability {
  appId: string;
  spaceId: string;
  creatorUserId: string;
  
  // Clamped by Creator's Role Rank (Viewer=1, Member=2, Editor=3, Admin=4, Owner=5)
  creatorRoleRank: number;
  // Granular Allowed Scopes
  grants: Array<{
    resource: "sqlite_db" | "mcp_tool" | "channel_notify" | "storage_bucket";
    target: string;        // e.g. "table:expenses", "slack:#warehouse-alerts"
    operations: Array<"read" | "write" | "delete" | "execute">;
    constraints?: {
      rateLimitPerMinute?: number;
      maxAmountCents?: number;
    };
  }>;
  expiresAt: number;
  signature: string; // HMAC-SHA256 signed with PLATFORM_SECRET
}
```
---
#### B. The Gatekeeper Interceptor on Micro-App Requests
Whenever a micro-app attempts an action (database write, Slack ping, or tool call), the **Gatekeeper Middleware** validates the capability token:
```typescript
// workers/router/src/gatekeeperMiddleware.ts
export async function enforceGatekeeper(
  req: Request,
  requiredGrant: { resource: string; target: string; op: "read" | "write" | "delete" | "execute" },
  platformSecret: string
) {
  const tokenHeader = req.headers.get("x-gatekeeper-token");
  if (!tokenHeader) throw new Error("Gatekeeper Violation: No capability token provided.");
  // 1. Verify cryptographic signature
  const capability = await verifyGatekeeperToken(tokenHeader, platformSecret);
  if (Date.now() > capability.expiresAt) throw new Error("Gatekeeper Violation: Token expired.");
  // 2. Verify Resource-Level Grant
  const isAuthorized = capability.grants.some(g => 
    g.resource === requiredGrant.resource &&
    (g.target === "*" || g.target === requiredGrant.target) &&
    g.operations.includes(requiredGrant.op)
  );
  if (!isAuthorized) {
    throw new Error(`Gatekeeper Block: App '${capability.appId}' lacks '${requiredGrant.op}' grant on '${requiredGrant.target}'.`);
  }
  return capability;
}
```

### 4. Implementation: The `MicroAppDO` Runtime
Every micro-app runs inside a dedicated Durable Object with **native SQLite storage**:
```typescript
// workers/spaces/src/do/MicroAppDO.ts
import { DurableObject } from "cloudflare:workers";
export class MicroAppDO extends DurableObject {
  private isInitialized = false;
  constructor(ctx: DurableObjectState, env: Env) {
    super(ctx, env);
  }
  async fetch(request: Request): Promise<Response> {
    const url = new URL(request.url);
    // 1. Serve Edge SSR Frontend (HTML/JS/Tailwind)
    if (url.pathname === "/" || url.pathname === "/app") {
      const appHtml = await this.ctx.storage.get<string>("app_bundle_html");
      return new Response(appHtml || "<h1>Micro-App Initializing...</h1>", {
        headers: { "content-type": "text/html" }
      });
    }
    // 2. Execute Private SQLite API Routes
    if (url.pathname.startsWith("/api/data")) {
      // Validate Gatekeeper capability token
      const token = request.headers.get("x-gatekeeper-token");
      await this.verifyGatekeeperAccess(token, request.method);
      if (request.method === "GET") {
        const rows = this.ctx.storage.sql.exec(`SELECT * FROM app_records ORDER BY created_at DESC`).toArray();
        return Response.json({ ok: true, data: rows });
      }
      if (request.method === "POST") {
        const body = await request.json() as any;
        this.ctx.storage.sql.exec(
          `INSERT INTO app_records (id, data_json, created_at) VALUES (?, ?, datetime('now'))`,
          `rec_${Date.now()}`, JSON.stringify(body)
        );
        return Response.json({ ok: true, message: "Record saved to private SQLite." });
      }
    }
    return new Response("Not Found", { status: 404 });
  }
  private async verifyGatekeeperAccess(token: string | null, method: string) {
    // Cryptographically checks that caller holds valid capability for this specific MicroAppDO
  }
}
```
