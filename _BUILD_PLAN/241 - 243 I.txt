### 2. How the Agent Evaluates Upstream Changes (Smart Reconciliation)
When an agent notices its scratchpad branch is behind `main`, it doesn't blindly fail. It runs an **Autonomous Upstream Impact Assessment**:
```typescript
// workers/agents/src/script-engine/prebuilt/git-sync.ts
export const checkAndReconcileUpstream = async (ctx: PrebuiltOpContext) => {
  const git = ctx.env.artifactsGit;
  const status = await git.getDivergenceStatus(ctx.env.projectId, ctx.env.threadId);
  if (status.commitsBehind === 0) {
    return { status: "UP_TO_DATE", message: "Branch is fully synchronized with main." };
  }
  // 1. Fetch exact git diff of what changed upstream on main
  const upstreamDiff = await git.getUpstreamDiff(status.baseCommit, status.upstreamHead);
  // 2. Compare upstream changed files with the files the agent is currently modifying
  const myActiveFiles = (await ctx.env.fs.glob("src/**/*")).files;
  const intersectingFiles = upstreamDiff.changedFiles.filter(f => myActiveFiles.includes(f));
  // 3. Decision Matrix
  if (intersectingFiles.length === 0) {
    // Zero overlap: Auto-rebase / Fast-forward cleanly
    await git.rebaseOntoMain(ctx.env.threadId);
    return {
      status: "AUTO_REBASED",
      commitsPulled: status.commitsBehind,
      message: `✔ Automatically pulled ${status.commitsBehind} upstream commits from main. Zero file collisions.`
    };
  }
  // Conflict Risk: Ask model to evaluate AST collision before pulling
  return {
    status: "REVIEW_REQUIRED",
    commitsBehind: status.commitsBehind,
    overlappingFiles: intersectingFiles,
    upstreamChangesSummary: upstreamDiff.summary,
    message: `⚠️ Upstream modified ${intersectingFiles.join(", ")}. Agent review required before merging.`
  };
};
```

# 4. Four More Game-Changing Capabilities with Cloudflare Artifacts
Because Cloudflare Artifacts gives you **tens of millions of real Git repositories running inside Durable Objects**, you can unlock capabilities that neither Claude Code nor GitHub can match:
---
### A. The Agent "Time Machine" (Turn-by-Turn Auto-Commits & 1-Click Rollback)
* **The Problem:** An agent runs 6 turns, and on turn 5 it introduces a subtle bug. In standard chat agents, you have to manually copy-paste old code or restart.
* **The Artifacts Solution:**
  * Every single tool turn in `loop.ts` automatically creates a lightweight Git commit:
    ```bash
    git commit -m "Turn 4: Applied patch to src/Header.astro [Task #2]"
    ```
  * In the thread UI, every message has a **[⏪ Revert Workspace to Here]** button. Clicking it runs `git reset --hard turn_3_commit_hash` in **5 milliseconds**, restoring the exact repository state of that turn without data loss.
```
Thread Timeline:
├── Message 1 (User): "Add Stripe checkout"
├── Turn 2 (Agent): Scaffolds `stripe.ts` ──► 🏷️ Commit `t2-scaffold` [⏪ Rollback]
├── Turn 3 (Agent): Adds webhook handler ──► 🏷️ Commit `t3-webhook`  [⏪ Rollback]
└── Turn 4 (Agent): Broken CSS patch     ──► 🏷️ Commit `t4-css-bug`  [⏪ Rollback]
```
---
### B. AI `git-blame` & Reasoning Attribution
When multiple agents and humans collaborate across a project, an agent often needs to understand **why a piece of code was written a certain way.**
* Every commit authored by an agent stores structured **Reasoning Front-Matter** in the Git commit message:
  ```yaml
  feat: add mutual indemnification clause in Section 4.2
  
  --AVOS-METADATA--
  author: "@LegalAgent"
  goal: "Review MSA for Delaware compliance"
  rationale: "Delaware Code § 145 limits unilateral indemnification for directors."
  task_id: "task_402"
  ```
* When another agent later inspects the file, it calls `git.blame("src/contracts/msa.md")` and reads **not just who wrote the line, but the exact legal/technical reasoning why they wrote it.**
---
### C. Automated Multi-Branch Race (Parallel Model Competition)
For high-difficulty, ambiguous coding tasks:
1. When a user runs `/goal Implement complex WebGPU physics shader`, the system creates **3 instant zero-copy Artifact forks in parallel**:
   * **Fork A:** Assigned to `Claude 3.7 Sonnet`
   * **Fork B:** Assigned to `Llama 3.3 70B`
   * **Fork C:** Assigned to `DeepSeek R1`
2. All 3 agents execute on their isolated branches and run `npm test`.
3. The platform scores the 3 branches:
   * Fork A passed 10/10 tests in 4 turns.
   * Fork B failed 2 tests.
4. The system presents Fork A's pull request to the user with full benchmark proof!
---
### D. Automated 3-Way AST Conflict Resolver Agent
If a PR submitted from a private scratchpad has conflicting edits with `main`:
1. The platform does not throw a dumb raw text conflict marker (`<<<<<<< HEAD`).
2. A specialized **Resolver Subagent** receives the 3-way AST diff:
   * Base commit ($O$)
   * Upstream changes on Main ($A$)
   * Scratchpad changes ($B$)
3. The agent inspects both intents, merges the non-overlapping AST nodes in Tier 2 CodeMode, runs the test suite, and presents a **verified, conflict-resolved merge commit**.
