# 1. The Concurrency Problem: Two Humans Chatting with the Same Bot
### The Question:
> *"What if Alice and Bob try chatting with `@DevBot` at the exact same second in the same project? Are they talking to two instances of the same bot, and how do they not corrupt the workspace?"*
### The Solution: The Per-Thread Actor Instance Model
In your Cloudflare Durable Object architecture, we cleanly separate **Conversational Memory** from **Authoritative Workspace State**:
```
                                  ┌──────────────────────────────────────────────┐
                                  │           PROJECT: "Core SaaS App"           │

                                                         │
                         ┌───────────────────────────────┴───────────────────────────────┐
                         ▼                                                               ▼
┌─────────────────────────────────────────────────────────────┐   ┌─────────────────────────────────────────────────────────────┐
│ 👩‍💻 THREAD 1: ALICE + @DevBot                               │   │ 👨‍💻 THREAD 2: BOB + @DevBot                                 │
├─────────────────────────────────────────────────────────────┤   ├─────────────────────────────────────────────────────────────┤
│ • **DO Actor ID:** `{thread_1}:{dev_bot}`                   │   │ • **DO Actor ID:** `{thread_2}:{dev_bot}`                   │
│ • **Private Memory:** Alice's conversation transcript.      │   │ • **Private Memory:** Bob's conversation transcript.        │

│ • **Zero Memory Bleed:** Doesn't see Bob's chatter.         │   │ • **Zero Memory Bleed:** Doesn't see Alice's chatter.       │
└──────────────────────────────┬──────────────────────────────┘   └──────────────────────────────┬──────────────────────────────┘

                                  │ Bob's @DevBot reads: "Sees PR #102 in review"│
```

#### How It Works:
1. **Isolated Ephemeral Brains:** Alice and Bob each get a dedicated `NaelaoAgentDO` actor instance for that thread. Alice's conversation with `@DevBot` never pollutes Bob's context window.
2. **Shared Living Ground Truth:** Both instances read and write to the **same Cloudflare Artifacts Git repository** and **Project Journal**.
3. **No Overwrite Collisions:** When Alice's `@DevBot` writes code, it commits to a **Git Branch (`branch:alice_darkmode`)**. When Bob's `@DevBot` writes code, it commits to **`branch:bob_stripe`**.

# 3. The 4 Golden Rules of the Multi-Bot Office
To ensure that multiple bots and multiple humans never create chaos in the project:
### Rule 1: All Code Changes Must Go Through Git Artifacts
* No bot or human is allowed to make silent, unversioned edits directly to `main`.
* Every bot creates a branch on **Cloudflare Artifacts (`git checkout -b ...`)**, applies patches, and submits a **Pull Request (PR)**.
### Rule 2: The Project Journal is the Authoritative Board
* The **Project Journal (`SpaceDO.tasks` table)** is the single source of truth for what has been done, what is in progress, and what is blocked.
* Before any bot starts a task, it checks the journal to verify that no sibling bot is already working on that component.
### Rule 3: Tier 3 System Consult Lanes for Bot-to-Bot Chatter
* When `@ArchitectBot` talks to `@DevBot` or `@ReviewBot`, they **do not spam the main human chat channel**.
* Their exchanges run in **Tier 3 System Consult Subthreads** (collapsed by default in the UI, expandable if a human wants to audit the raw multi-agent reasoning).
### Rule 4: Slack-Style `@Mentions` in Public Channels
* In public project rooms (Tier 1 Team Room & Tier 2 Task Threads), bots **remain silent** unless explicitly addressed with `@DevBot`, `@ReviewBot`, or `@Assistant`.

# 4. The 7 Critical Challenges & Their Cloudflare Solutions
---
### Challenge 1: Same-Thread Human Concurrency
> **The Problem:** Alice and Bob type messages to `@DevBot` at the exact same millisecond in the **same public thread**. Does the bot crash, reply twice, or clobber context?
#### The Cloudflare Solution: In-DO Message FIFO Queue + Streaming Pacing
Because `NaelaoAgentDO` is a single-threaded actor in Cloudflare Durable Objects:
1. **Atomic Sequence Ordering:** Alice's message is assigned `seq: 101` and Bob's is assigned `seq: 102` in SQLite.
2. **Execution Pacing:** The DO handles Alice's turn first.
3. **Live UI Feedback for Bob:** While `@DevBot` is writing to Alice, Bob's message shows a live indicator in the chat:  
   `[ ⏳ Queued — @DevBot is answering Alice's message... ]`
4. As soon as Alice's turn completes, `@DevBot` immediately processes Bob's message with full context of what it just told Alice.
---
### Challenge 2: Credential Isolation in Multi-User Shared Projects
> **The Problem:** Alice connects her **personal Gmail/Google Calendar** so `@DevBot` can check her schedule. What if Bob prompts `@DevBot`: *"Send an email from Alice's Gmail saying I'm taking the week off"*?
#### The Cloudflare Solution: Cryptographic Identity Attestation (Zero Privilege Escalation)
Every personal credential in `workers/credentials` is encrypted with the owning user's ID (`scope: "user"`, `user_id: "usr_alice"`):
1. When Bob sends a message, his request carries `x-naelao-user-id: usr_bob`.
2. When `@DevBot` attempts to call `gmail.send`, the **Credentials Worker** evaluates:  
   `acting_user_id (bob) !== credential_owner_id (alice)`.
3. The runtime **physically refuses to decrypt Alice's token for Bob's turn**, throwing an immediate security error:  
   `✖ 403 Forbidden: Bob cannot execute actions using Alice's personal Gmail credential.`
4. Even if Bob executes a sophisticated prompt injection, **the credentials worker will never release the decrypted key.**
---
### Challenge 3: Shared Workspace Resource Contention & Container Queueing
> **The Problem:** 4 bots in the same project try to run `npm run build` or `python train.py` in Tier 6 Containers at the same time.
#### The Cloudflare Solution: Tier 6 Task Queueing via `ConcurrencyDO`
* Tier 1 (SQLite FS) and Tier 2 (Isolates) execute concurrently in parallel V8 contexts (zero contention).
* For heavy Tier 6 Container tasks, `ToolSandboxDO` acquires a lock through `ConcurrencyDO`.
* If `@DevBot` is already running a build, `@QABot`'s build task enters a lightweight queue for 3 seconds until the container finishes, then executes without restarting the isolate.

### Challenge 7: Infinite Loop & Budget Runaway Protection
> **The Problem:** Two bots get stuck in a ping-pong loop (Bot A triggers Bot B, which triggers Bot A).
#### The Cloudflare Solution: The 3-Layer Loop Circuit Breaker
1. **`trace_id` Depth Counter:** Every event carries a propagation depth counter `depth: number`. If `depth > 4` across bot-to-bot delegations, the runtime halts the cascade.
2. **Project Daily Spend Cap (`SpaceDO.project_spend`):** If a bot loop burns through the project's configured daily credit limit (e.g. 500 credits = $5.00), `SpaceDO` **refuses all further tool turns** and sends a Telegram alert to the founder.
3. **Stall Detector (`loop-budget.ts`):** If a bot produces no new state change or git diff after 4 turns, the loop forces a terminal summary and stops.
