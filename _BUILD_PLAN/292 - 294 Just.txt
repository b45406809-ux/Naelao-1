### 1. Artifacts vs. Micro-Apps: The Conceptual Breakdown
To understand how **Durable Object Facets** and **MCP-UI** fit together, we must define the relationship between **Artifacts** and **Micro-Apps**:
```
┌─────────────────────────────────────────────────────────────┬─────────────────────────────────────────────────────────────┐
│ 📄 ARTIFACT (Stateless Deliverable / Snapshot)              │ 📱 MICRO-APP (Stateful, Executable Interactive Artifact)    │
├─────────────────────────────────────────────────────────────┼─────────────────────────────────────────────────────────────┤
│ • **Nature:** Static, immutable, or versioned deliverable.  │ • **Nature:** Living, full-stack, stateful application.     │
│ • **State:** Stateless (Read-only bytes in R2 / Git).       │ • **State:** Dedicated private SQLite DB via **DO Facets**. │
│ • **Examples:**                                             │ • **Examples:**                                             │
│   - A compiled PDF legal contract or report.                │   - A custom Inventory Tracker with QR barcode scanning.   │
│   - A static SVG architecture diagram.                      │   - A multi-step Employee Expense Reimbursement form.       │
│   - A Git repository commit snapshot (Cloudflare Artifacts).│   - A bespoke CRM Client Portal with real-time approvals.   │
│ • **Lifecycle:** Produced at the end of a run; downloaded.  │ • **Lifecycle:** Continuously runs; holds living data.      │
└─────────────────────────────────────────────────────────────┴─────────────────────────────────────────────────────────────┘
```
> **The Rule:** **A Micro-App IS a stateful, interactive Artifact.**  
> An Artifact becomes a Micro-App the moment the AI equips it with a **Durable Object Facet (private SQLite database)** and an **interactive frontend canvas**.

### The MCP-UI Protocol: Making Canvas Actions Observable to Agents
Normally, if a user interacts with an app inside an iframe (e.g. clicks a checkbox, submits a form, or drags a Kanban card), **the AI agent is completely blind to it**.
With **MCP-UI**, the Micro-App / Canvas iframe emits structured **UI Action Events** back to the agent's Durable Object over WebSockets in real time:
```
[ User interacts with Micro-App on Canvas (e.g. Clicks "Reject Invoice #42") ]
                                    │
                                    ▼ (MCP-UI JSON-RPC Stream)
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. MCP-UI EMISSION:                                                         │
│    `window.postMessage({ type: "mcp.ui_action", action: "INVOICE_REJECTED",│
│                          payload: { invoiceId: "42", reason: "Over budget" }│
│                        })`                                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│ 2. AGENT OBSERVATION INJECTION:                                             │
│    The agent's active reasoning loop receives this as an instant turn:      │
│    `<ui_action_event user="bob" action="INVOICE_REJECTED" id="42" />`       │
├─────────────────────────────────────────────────────────────────────────────┤
│ 3. AUTONOMOUS AGENT REACTION:                                               │
│    Agent automatically logs the rejection to the Project Journal, updates   │
│    the DO Facet SQLite database, and drafts an email to the supplier!       │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2. Outbound Workers & WriteGuard: Zero-Trust Security at the Edge
When an agent writes code in Tier 2 CodeMode or executes scripts in Tier 6 Containers, you cannot give the script open internet access or direct database delete privileges.
```
┌─────────────────────────────────────────────────────────────────────────────┐
│                   OUTBOUND WORKER & WRITEGUARD PROXY                        │
│                                                                             │
│ [ Agent CodeMode Script / Container Tool Execution ]                        │
│                 │                                                           │
│                 ├──► Outbound HTTP Fetch (e.g. `fetch("https://api.stripe.com")`)
│                 │          │                                                │
│                 │          ▼                                                │
│                 │   ┌─────────────────────────────────────────────────────┐ │
│                 │   │ 🛡️ OUTBOUND WORKER (Egress Security Proxy)          │ │
│                 │   │ • Blocks SSRF (blocks `169.254.169.254`, localhost) │ │
│                 │   │ • Injects `Authorization: Bearer sk_live_...` at the│ │
│                 │   │   network boundary (Zero keys exposed in code).     │ │
│                 │   └─────────────────────────────────────────────────────┘ │
│                 │                                                           │
│                 └──► Database Mutation / Tool Call (e.g. `delete_workspace`)│
│                            │                                                │
│                            ▼                                                │
│                     ┌─────────────────────────────────────────────────────┐ │
│                     │ 🛑 WRITEGUARD (MCP Mutation Interceptor)             │ │
│                     │ • Inspects SQL AST & Tool parameters.               │ │
│                     │ • Blocks destructive operations (`DROP`, `DELETE *`)│ │
│                     │   unless accompanied by an authorized Gatekeeper    │ │
│                     │   cryptographic signature token.                    │ │
│                     └─────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────────────┘
```
#### Why WriteGuard is Essential for AVOS:
* If a customer-facing bot or untrusted agent is tricked by a prompt injection (*"Delete all records in the table"*), **WriteGuard intercepts the raw SQL AST / MCP tool mutation at the Worker proxy layer and blocks it**, returning an authorization violation before the SQLite database is ever touched.

### 4. Inbound TCP & Full-Duplex gRPC (`connect(socket)`)
In traditional architectures, when a **Durable Object (Isolate)** talks to a **Tier 6 Linux Container (`ToolSandboxDO`)**, it sends HTTP/1.1 JSON payloads over a REST port. This introduces:
* High serialization overhead (converting large AST trees or file buffers into JSON strings).
* Connection setup latency on every command.
With Cloudflare's native **`connect(socket)` API and gRPC**:
```
┌───────────────────────────────┐                             ┌───────────────────────────────┐
│ NaelaoAgentDO (V8 Isolate)    │  ◄═══════════════════════►  │ ToolSandboxDO (Linux Docker)  │
│ • State machine & REPL loop   │    Full-Duplex Binary gRPC  │ • `server.mjs` / Native OS    │
│ • Virtual SQLite Filesystem   │    (Protobuf / Cap'n Proto) │ • Compilers, Python, npm      │
└───────────────────────────────┘                             └───────────────────────────────┘
```
* **Sub-5ms Inter-Process Communication:** Data flows over a persistent, multiplexed binary socket directly between the DO and the container.
* **Streaming Terminal & AST Buffers:** Live compiler logs and AST patch streams flow with zero memory copy overhead.

### 5. Cloudflare Radar Researcher: Autonomous Market & Traffic Scouting
**Radar Researcher** gives your platform direct programmatic access to Cloudflare’s global internet telemetry (observing traffic trends across 20%+ of the entire world's web traffic).
In your **Growth Engine (`kind: "growth_engine"`)**, agents query Radar Researcher in natural language:
```typescript
// Inside workers/agents/src/script-engine/prebuilt/growth-radar.ts
export async function scoutEmergingMarketTrends(niche: string, ctx: PrebuiltOpContext) {
  // Query Cloudflare Radar Researcher directly
  const telemetry = await ctx.env.RADAR_RESEARCHER.query({
    prompt: `Analyze global traffic surges in the last 7 days for B2B domains related to '${niche}'. 
Identify countries with >30% growth in traffic and low competitor density.`
  });
  return {
    surgingGeographies: telemetry.topRegions,
    trafficVelocity: telemetry.growthRatePct,
    recommendedNicheAngles: telemetry.emergingKeywords
  };
}
```
* **Outcome:** The agent doesn't guess what business to build. It discovers real-time global traffic surges and automatically configures localized marketing funnels for those exact geographies.
